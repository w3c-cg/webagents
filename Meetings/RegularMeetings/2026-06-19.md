#### HyperAgents ontologies

Github repo: [https://github.com/HyperAgents/hmas](https://github.com/HyperAgents/hmas)

Documentation of core ontology: [https://purl.org/hmas/core](https://purl.org/hmas/core)

Doc of the interaction ontology: [https://ci.mines-stetienne.fr/hmas/interaction](https://ci.mines-stetienne.fr/hmas/interaction)

Doc of the regulation ontology: [http://purl.org/hmas/regulation](http://purl.org/hmas/regulation)

Antoine introduced the need for the hmas (Hypermedia MAS) ontology and its modules developed during the HyperAgents collaboration project.

The project used and partially developed the Ontology engineering methodology.

The terms in the ontology have broad definitions.

Ege: what is meant by autonomous? Difference Autonomous and Automate?

Antoine: Broader sense of the concept to be inclusive.

Gustavo: Autonomous is an entity that has the capability of making decisions shaped by on their own knowledge, for instance, belief and goals.

Jérémy: Signifier in the ontology is defined in a broader sense. For example, piece of Thing Description (TD) on the web could be a signifier. More recently, signifier has been used to signal only behavior possibility.

Jérémy: Shared some definitions  or clarifications of the Agent, and Artifact and its distinction to Tools concepts.

"The interoperability report also has a definition for agent: An entity situated in an environment that perceives its environment and acts on it, over time, in pursuit of its goals. For a detailed discussion of agent definitions, see [FRANKLIN96]."

"There is also a definition for "Tool or Artifact": An instrument that can be shared and used by agents to support their activities. In some multi-agent systems, agents construct artifacts to instrument their environments [JACAMO20]. In the context of agentic AI, a tool is a functional interface to a program that a language model can invoke. Tools extend the capabilities of LLMs by enabling them to retrieve knowledge not seen during training, perform complex computations, mitigate hallucinations, and perceive or act in an environment [TOOL]."

Antoine: Are the concepts in the core well placed? Is there any missing concept in the core?

Andrei: Isn't missing concepts in the core to represent Organization concepts?

Antoine: We have a module called Regulation ontology that details more the Organization concepts.

Gustavo: some organisation may have an oganisation specification but not all. This is done by using the extension module on regulation.

Jérémy: The Interaction ontology has few approved concepts and integrated into the official repository, but there are more concepts that has not been finalized.

Antoine: Does anyone know about any similar initiative in the knowledge representation?

Antoine: Semantic Agent Communication Community Group ([https://www.w3.org/community/s-agent-comm/)](https://www.w3.org/community/s-agent-comm/)) are dedicated to develop ontologies in the agent domain. They tackle a wider set of concepts, but the ontology is very lightweight.

Antoine: Add in the Interoperability Report a mention the these other initiatives.

Jérémy: Is there a plan to improve the ontology ?

Antoine: Not officially. There are some project proposal submitted that may lead to the use and extend the ontologies.

Jérémy: The hmas ontology could be used as the basis for LLM-based systems.

Antoine: Finish the Interoperability Report will give a better view on what is required to improve/extend the hmas ontology. It would be better to have official projects to dedicate time and resource to develop the ontology.

Jérémy: Problem of uneven among groups participating in the development since we have a large set of participants that may not participate in the official projects.

Antoine: WebAgents CG can serve as a bridge between the development in the official projects and the other outside of the project.
